## System derived from the assessment

### Depth

1. **Recognition** — the homepage communicates proposition, problem, connected capabilities, selected proof, engagement logic, operating principles, and conversion in a short scan.
2. **Exploration** — Capabilities, Process, Work, and About allow rapid route-level scanning before detail is opened.
3. **Evidence** — dossiers retain technical and operational density, with explicit parent, section, capability, and next-record context.

### Composition vocabulary

- **Editorial statement:** one consequential heading and one supporting thought.
- **System visual:** boundaries, states, ownership, or transformations carry the explanation.
- **Split narrative:** idea and evidence receive unequal but related space.
- **Transformation:** fragmented condition resolves through a defined boundary.
- **Selected proof:** one dominant record and one supporting record.
- **Sequence:** state and output are legible before stage detail.
- **Principle:** a compact operating commitment, not a mini-essay.
- **Immersive hinge:** one inverse conceptual interruption per long recognition page.

Adjacent sections must not repeat the same composition. Ledgers and rules are reserved for ordinal, indexical, legal, or dossier content; they are not default substitutes for composition.

### Wayfinding

- The approved masthead gains a quiet `aria-current` state using one neutral hairline.
- Exploration routes identify their page family and current route.
- Dossiers identify Selected Work as their parent, provide an explicit return path, retain a local section index, expose related capabilities, and end with a next-system route.
- Contact, Portal, and Privacy use a minimal `Brunova / Route` context trail.

### Responsive density

Mobile receives the same editorial reduction as desktop. Visual relationships recompose into short vertical state sequences; deep content remains closed until requested. Spanish may occupy more vertical space while preserving the same hierarchy and type scale.

## Implementation boundary

This increment changes shared hierarchy, disclosure, visual vocabulary, and route orientation. It does not perform detailed per-route cosmetic refinement, add external imagery, change the approved masthead structure, alter application behavior, or begin Phase 9.
